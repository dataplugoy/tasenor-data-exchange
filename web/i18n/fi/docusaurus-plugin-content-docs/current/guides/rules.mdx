# Säännöt (english)

The rule system uses a custom programming language for transaction processing.

<figure>
<figcaption>**Example**: A rule handling withdrawal from Nordnet.</figcaption>
```json
  {
    "name": "Deposit",
    "filter": "Tapahtumatyyppi == 'TALLETUS'",
    "key": "TALLETUS",
    "result": {
      "type": "'deposit'",
      "value": "Summa",
      "valueAsset": "Valuutta",
      "service": "'Nordnet'"
    }
  }
```
</figure>

The rule set for an information source is an array of JSON objects, like the one shown above. It contains the following fields:
* **name** Display name for the rule.
* **filter** The expression is executed and the first true value determines the calculated result based on the matching rule.
* **key** The driver may pick a dedicated field from the source data that can speed up finding a matching rule. In this example, the driver can pick the field “Tapahtumatyyppi” as a good lookup key since it is used in every rule filter.
* **result** When the matching rule is found, each field is evaluated to produce a [unified format](./unified-format) item as the result.

<figure>
<figcaption>**Example 2**: After the match, a result is found and evaluated.</figcaption>
```json
  {
    "type": "deposit",
    "value": "2500.00",
    "valueAsset": "EUR",
    "service": "Nordnet"
  }
```
</figure>



## Mapping Rules and Advanced Rules

Rules of a flow plan come in two kinds:

* **Mapping rules** are edited with forms in the rule editor: a list of conditions and an action. They are
  compiled to the `filter` and `result` expressions described above. See [Bank Statements](./bank-statements).
* **Advanced rules** are written directly as expressions and edited as JSON.

Rules coming with the driver of the information source are *default rules*. When the driver is updated, its
default rules are updated too, but rules created or edited by the user are never changed automatically. A rule
can also be disabled, in which case it is not used.

If no rule matches an item, the user is asked how to handle it. The answer is stored as a *one-off answer* for
that item and used instead of the rules when the item is processed again.

In addition to the functions below, expressions may use `matches(regex, value)` which tests a regular expression
ignoring case and always returns true or false.

## Functions

Besides basic constants, variables, and arithmetic, the rule includes numerous functions to utilize.

Core is based on the [MathJS](https://mathjs.org) and so [all MathJS features and functions](https://mathjs.org/docs/index.html) are available.

[All MathJS features and functions](https://mathjs.org/docs/index.html) are accessible in Core since it’s built on [MathJS](https://mathjs.org).

Furthermore, there are certain custom functions documented at [https://docs.stg.tasenor.com/api/tasenor-common/class/RulesEngine](https://docs.stg.tasenor.com/api/tasenor-common/class/RulesEngine)
