# Yhteisformaatti (english)

The unified format is a comprehensive JSON format that represents all the supported transactions that TaDeX can understand. It also permits a certain level of incompleteness. If an issue can be solved through analysis, it can be disregarded. For instance, if the current exchange rate is not provided, it can be obtained from a third party as long as the transaction date is known.

## Types

### Enum

An enumerated type is a fixed list of accepted string values.

### Number

A number type is an actual number or a string that can have arbitrary precision.

### String

A string is UTF-8 encoded string possibly limited by some regular expression pattern.

### Asset

An asset is a special string type that refers to the ISO-4217 currency codes, stock ticker or crypto currency symbol.

### Asset Type

An asset type can be classified as either STOCK or CRYPTO.

### Map

A key-value mapping, known as a map, uses string keys to link to arbitrary values.


## Common Fields

### `type` <Type file="UnifiedItemData.json" field="type"/>

This defines the idea of the transaction. Each type of transaction has different fields it requires by default and some fields it can determine according to the type. Supported types are <TxTypes/>.

### `value` <Type file="UnifiedItemData.json" field="value"/>

This field is used to calculate the total transaction value, including additional fees, for example. There are two ways to input a value: as a number or as a high-precision string. The default currency in the flow plan measures value.

### `text` <Type file="UnifiedItemData.json" field="text"/>

The default language of the flow plan allows for individual descriptions of many transaction types. If there’s a text field, it replaces the default text.


## Some Optional Fields

### `valueAsset` <Type file="UnifiedItemData.json" field="valueAsset"/>

It is unnecessary to define total value in default currency. If a different currency or crypto currency is used, this field can specify it.

### `rates` <Type file="UnifiedItemData.json" field="rates"/>

If the exchange rates from other currencies to the default currency are known, they can be provided here. Alternatively, it can be resolved using different services. The field format consists of a mapping that includes the name(s) of the currency or asset and their corresponding conversion rate(s) in the default currency. The single unit of the target asset has a value of 1.0 in the default currency.

## Assets

### `assetIn` <Type file="UnifiedItemData.json" field="assetIn"/>

In buy transactions and similar situations, we receive an asset. This field serves as an identifier for assets like cryptocurrencies, stock tickers, or similar items.

### `assetAmountIn` <Type file="UnifiedItemData.json" field="assetAmountIn"/>

This field displays the amount of units of the asset received here.

### `assetValueIn` <Type file="UnifiedItemData.json" field="assetValueIn"/>

Default currency value can be defined here if already known. If not, value is determined from other sources.

### `assetTypeIn` <Type file="UnifiedItemData.json" field="assetTypeIn"/>

Specifies the asset type received.

### `assetOut` <Type file="UnifiedItemData.json" field="assetOut"/>

Similar to `assetIn` but when giving away an asset.

### `assetAmountOut` <Type file="UnifiedItemData.json" field="assetAmountOut"/>

Similar to `assetAmounIn` but when giving away an asset.

### `assetValueOut` <Type file="UnifiedItemData.json" field="assetValueOut"/>

Similar to `assetValueIn` but when giving away an asset.

### `assetTypeOut` <Type file="UnifiedItemData.json" field="assetTypeOut"/>

Similar to `assetTypeIn` but when giving away an asset.


## Fees

Transactions, such as buying or selling stocks, have a separate line item for the fee, distinguishing it from the expense. Each expense is a separate and independent transaction.

### `fee` <Type file="UnifiedItemData.json" field="fee"/>

The fee charged for the transaction.

### `feeAsset` <Type file="UnifiedItemData.json" field="feeAsset"/>

The fee charged for the transaction.


## Taxes

A tax is similar to a fee, but it goes to the tax collector instead of the service provider.

### `taxType` <Type file="UnifiedItemData.json" field="taxType"/>

A type of the tax charged. Currently, either `vat` or `withholding` tax is applicable.

### `taxAmount` <Type file="UnifiedItemData.json" field="taxAmount"/>

The exact tax amount, if known, is provided here.

### `taxAsset` <Type file="UnifiedItemData.json" field="taxAsset"/>

This field specifies the tax amount, if it is given in a currency or asset other than the default.

### `taxPercentage` <Type file="UnifiedItemData.json" field="taxPercentage"/>

The tax amount can be provided as a percentage of actual income or expense, instead of the exact amount.


## Miscellaneous

### `balance` <Type file="UnifiedItemData.json" field="balance"/>

The balance field provides a hint for when the account should be zero. It’s useful for trimming rounding errors from forex conversions. The analyser compares the running balance to zero and records profit or loss.

### `multipart` <Type file="UnifiedItemData.json" field="multipart"/>

Where the input items cannot form complete transaction alone, they can be given individually. If that’s the case, every item needs to have a specific identifier listed in this section. When processing, parts with identical multipart fields are combined into one. The combined result cannot be guaranteed if there are overlapping fields with different values.

### `reason` <Type file="UnifiedItemData.json" field="reason"/>

In order to translate text into transactions, predefined reason symbols are automatically utilized when constructing automatic text for income and expenses. Currently reason can be one of the following: <EnumValues file="UnifiedItemData.json" field="reason"/>.

### `reasonAsset` <Type file="UnifiedItemData.json" field="reasonAsset"/>

Sometimes the asset needs to be referenced in the automatic text generation. For example, having details of a stock ticker paying dividends is preferred.

### `service` <Type file="UnifiedItemData.json" field="service"/>

Name of the service providing the data. Used in automatic text generation for service withdrawals or deposits, for example.

### `tags` <Type file="UnifiedItemData.json" field="tags"/>

Tags are arbitrary non-empty strings attached to the transaction. Typically, these can be used as dimensions in the destination bookkeeping. The field should be an array if it exists in the rule.
